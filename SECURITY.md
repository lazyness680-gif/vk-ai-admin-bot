## 2. Модель угроз

| Угроза | Что может случиться | Защита |
|---|---|---|
| Кража API-ключа | Чужие запросы за ваш счёт | Ключи только в `.env`, `.gitignore`, маскирование в логах, ротация |
| Prompt injection | Клиент заставляет бота забыть правила, выдать промпт, оскорбить, пообещать скидку | Текст клиента помечен как данные, отдельный блок правил безопасности, эвристика на 16 паттернов, ограничение темы |
| Выдуманная запись | Бот «записал» на занятое время | Время берётся только из `get_free_slots`; `book_slot` атомарно перепроверяет слот |
| Флуд и спам | Дорогие запросы к модели, блокировка сообщества | Лимит 10/мин и 80/час на пользователя, дневной лимит 2000 запросов |
| SQL-инъекция | Кража или порча базы | Параметризованные запросы, нет конкатенации пользовательских данных |
| Формульная инъекция в Excel | Выполнение формулы при открытии таблицы администратором | Префикс `'` для значений, начинающихся с `=`, `@`, `+`, `-` (кроме телефонов) |
| Утечка персональных данных в логи | Телефоны и имена в открытом виде | Логи пишут только события; телефоны в логи не попадают |
| Подмена сообщений / повторная обработка | Дубли записей после рестарта | Дедупликация по `peer_id:message_id` в SQLite |
| Кража файла `leads.xlsx` | Утечка базы клиентов | Файл вне git, доступ по ACL, рекомендации ниже |
| Медицинская ошибка | Вред здоровью + претензии | Запрет диагнозов и лечения, только запись к оптометристу |
| Утечка системного промпта | Конкурент видит скрипты | Запрет раскрывать промпт, технические разделы в модель не попадают |

## 3. Что сделано в коде

### 3.1. Секреты

- Все ключи — только в `.env` (файл в `.gitignore`).
- В коде нет ни одного ключа; тесты используют заглушки `sk-test` / `vk1.a.test`.
- `SecretFilter` в логировании вырезает `sk-…`, `vk1.a.…`, `Bearer …` из всех записей.
- Ответ модели проходит через `mask_secrets()` — если модель «повторит» ключ, он не уйдёт клиенту.
- `config.py` проверяет: ключ ProxyAPI начинается с `sk-`, базовый URL только `https://`, ID сообщества — положительное число.

### 3.2. Ввод и вывод

- `sanitize_input()`: Unicode-нормализация, удаление управляющих и невидимых символов (обход фильтров, RTL-override, zero-width), обрезка до 2000 символов.
- `sanitize_output()`: маскирование секретов, обрезка до 3800 символов, разбивка на части под лимит VK 4096.
- `looks_like_injection()`: 16 маркеров попытки подмены инструкций → в запрос добавляется служебная пометка, бот не выполняет команду, но продолжает помогать.
- Промпт содержит отдельный блок «Безопасность» с приоритетом выше рабочих инструкций.

### 3.3. Запись

- `slot_id` строго валидируется регуляркой: дата, время, имя мастера. Строка вида `../../etc/passwd` отбрасывается.
- `book_slot` проверяет: согласие, имя, телефон, принадлежность услуги мастеру, рабочие часы, обед, пересечение с другими записями, горизонт 30 дней.
- Создание записи — транзакция `BEGIN IMMEDIATE`: два одновременных клиента не займут один слот.
- Повторная запись того же клиента на тот же день блокируется.

### 3.4. Персональные данные

- Собирается минимум: имя, телефон, услуга, время. Паспорт, адрес, СНИЛС, карты — запрещены промптом.
- Без `pd_consent=true` телефон **не сохраняется** — проверка на двух уровнях (инструмент + хранилище).
- В Excel есть колонка «Согласие на ПД» со значениями `да`/`нет`.
- Согласие спрашивается до сохранения номера, формулировка в промпте: «Данные передаю администратору только для записи — вы не против?».
- Уведомления о записях уходят в личные сообщения ВК только на `ADMIN_VK_ID` (личный аккаунт владельца). Это внешняя передача контактов через ВК — следствие выбранного канала; данные клиента видит только владелец аккаунта.

### 3.5. Инфраструктура

- Только HTTPS: VK API и ProxyAPI.
- Таймауты: LLM — 45 с, VK — 35 с, Long Poll — 50 с; ретраи с backoff.
- `follow_redirects=False` — ключ не уйдёт на чужой хост.
- Дневной лимит запросов к модели — защита от «сожжённого» баланса.
- Один процесс на сообщество, SQLite в WAL, `busy_timeout` 5 секунд.

## 4. Что нужно сделать владельцу

### 4.1. Обязательно

- [ ] Заполнить `.env` и **никогда** не пересылать его в мессенджерах и не выкладывать в репозиторий.
- [ ] Ограничить доступ к папке проекта средствами Windows: правый клик → Свойства → Безопасность → оставить только свою учётную запись и `Администраторы`.
- [ ] Включить BitLocker на диске с `data/` — там `leads.xlsx` и `bot.db` с телефонами клиентов.
- [ ] Не держать проект в облачных папках (OneDrive, Яндекс.Диск, общие диски).
- [ ] Настроить резервное копирование `data/` (зашифрованный архив, срок хранения — не дольше необходимого).
- [ ] Проверить, что `ADMIN_VK_ID` указывает на ваш личный аккаунт, а не на общий.
- [ ] Ротировать ключи раз в 6–12 месяцев и сразу — при утечке или увольнении сотрудника с доступом.

### 4.2. По 152-ФЗ (Россия)

Бот обрабатывает персональные данные клиентов. До запуска в работу:

- [ ] Убедиться, что салон подал уведомление в Роскомнадзор об обработке ПД (если ещё не подавал).
- [ ] Опубликовать политику обработки ПД и получить согласие клиента (бот спрашивает согласие в чате — фиксируется в Excel).
- [ ] Определить срок хранения заявок (например, 12 месяцев) и настроить удаление старых строк.
- [ ] Назначить ответственного за обработку ПД.
- [ ] Хранить данные только на территории РФ (локальный компьютер салона подходит).

### 4.3. Желательно

- [ ] Ограничить доступ к `logs/bot.log` — там переписка без телефонов, но с контекстом.
- [ ] Раз в неделю просматривать `data/outbox.jsonl` и удалять после успешной выгрузки.
- [ ] Проверять, что в `.env` не осталось `DEBUG` и тестовых значений.
- [ ] Запускать `python scripts/security_audit.py` после каждого изменения кода.

## 5. Остаточные риски

| Риск | Оценка | Комментарий |
|---|---|---|
| Данные на диске не зашифрованы | Средний | SQLite и Excel — открытые файлы. Решается BitLocker + ACL |
| Модель может ошибиться в формулировке | Низкий | Цены и слоты берутся из кода, не из «памяти» модели; спорные случаи уходят человеку |
| Фото не анализируются | Низкий | Бот честно просит описать словами; нет ложной оценки по фото |
| Владелец копирует `.env` на другой компьютер | Средний | Ключи действуют везде; храните только на рабочей машине |
| Открытый Excel блокирует выгрузку | Низкий | Outbox + повтор через минуту |
| Модель отвечает не по-русски | Низкий | Промпт требует русский; при сбое — шаблонный ответ |
| Долгий ответ API | Низкий | Таймаут 45 с, затем извинение и передача администратору |

## 6. Известные ограничения

1. **Нет шифрования данных at rest** — это задача ОС (BitLocker) и прав доступа.
2. **Нет веб-панели** — администратор смотрит Excel; совместного доступа с ролями нет.
3. **Нет автоматических напоминаний клиенту** — дата напоминания пишется в Excel, отправка остаётся за администратором. Для автоматики нужен планировщик рассылок.
4. **Фото оправ — ссылкой**, а не вложением.
5. **Один бот — одно сообщество.** Для сети салонов нужен отдельный процесс и отдельная БД на каждое сообщество.

## 7. Если произошла утечка

1. Немедленно отозвать ключ ProxyAPI в кабинете и выпустить новый.
2. Перевыпустить ключ сообщества ВКонтакте (старый отзывается автоматически).
3. Заменить значения в `.env`, перезапустить бота.
4. Проверить `logs/bot.log` на подозрительные запросы и баланс ProxyAPI на списания.
5. Оценить, какие данные могли уйти, и при необходимости уведомить Роскомнадзор (72 часа по 152-ФЗ).
6. Сменить пароли от компьютера и кабинета ProxyAPI.

## 9. Что проверено тестами

- Маскирование `sk-…` и `vk1.a.…` в тексте и логах.
- Удаление невидимых и управляющих символов из ввода.
- Обрезка длинного ввода и вывода.
- Распознавание 16 маркеров prompt injection.
- Валидация и нормализация телефона (все форматы РФ, мусор отбрасывается).
- Валидация имени (цифры и символы не проходят).
- Нейтрализация формул Excel (`=`, `@`, `+`, `-`).
- Лимиты: 10 сообщений в минуту, 80 в час.
- Слоты: обед, прошедшее время, занятые часы, чужой мастер, выходной, удержание.
- Двойная запись на один слот — блокируется.
- Запись без согласия, с плохим телефоном, с поддельным `slot_id` — отклоняется.
- Телефон без согласия не попадает в Excel.
- Сквозной сценарий: сообщение → `get_free_slots` → `book_slot` → строка в Excel → подтверждение клиенту.
- Дубли сообщений, сообщения сообщества, исходящие — игнорируются.
- Сбой LLM → извинение + передача администратору.
- Попытка инъекции → пометка в запросе, бот продолжает работу.
